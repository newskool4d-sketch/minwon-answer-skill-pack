# 인용 검증 프로토콜

답변에 인용하는 모든 법령·행정규칙·자치법규·판례는 발송 전 공식 원문으로 검증한다. 기억, 요약자료, 과거 답변 사례의 인용문을 그대로 옮기지 않는다. 잘못된 조문 인용은 답변 전체의 신뢰를 무너뜨리고, 재민원·고충민원·행정심판 단계에서 기관의 절차적 약점으로 남는다.

## 검증 절차 (korean-law-mcp)

인용할 조문마다 다음 순서로 확인한다.

1. `search_law` — 법령 존재 여부, 시행일자, 소관부처를 확인한다. 개정·제명변경·시행예정(🔜) 여부를 함께 본다.
2. 적용 버전 확정 — 아래 「적용 버전 확인」에 따라 적용 기준일을 정하고, 현행본과 적용 버전이 같은지 확인한다.
3. `get_law_text` — 적용 버전의 조문 전문을 그대로 가져와 인용한다(현행이면 `efYd` 없이, 과거 기준일이면 `efYd=기준일`). 항·호 구조와 `<개정 …>` 표기를 유지한다. `<개정>` 일자가 참고자료보다 최신이면 참고자료가 아니라 조회한 조문을 따른다.
4. `legal_analysis` (verify_citations 모드) — 초안 완성 후 인용 전체를 일괄 점검한다. 조문 존재 여부와 조문 제목 불일치(예: "제750조(계약해제)" 류 오류)를 잡는다. 이 점검은 현행본 기준이므로, 과거 버전 조문을 인용했으면 같은 번호의 현행 조문이 있다는 이유로 통과할 수 있다. 과거 버전 문언은 2~3단계 조회로 확인한다.
5. 행정규칙(고시·훈령·예규·지침) — 서버에 전용 도구가 보이지 않으면 `discover_tools`로 사용 가능한 도구를 확인하고(`execute_tool` 경유 포함), 없으면 law.go.kr 행정규칙 검색으로 수기 확인한다.
6. 판례 — `search_decisions`, `get_decision_text`로 확인한다.
7. 조례·교육규칙 — 자치법규는 `ordinance_radar` 또는 law.go.kr 자치법규 검색으로 확인한다. 교육청 답변은 조례·교육규칙 근거가 잦으므로 생략하지 않는다.

인용 1건당 조회 1회를 원칙으로 하고, 아래 인용 검증표 양식의 모든 칸을 채운다.

## 적용 버전 확인: 현행 여부와 사안 적용 버전 구분

두 질문을 따로 확인한다.

| 질문 | 확인 방법 |
|---|---|
| 이 조문이 지금 시행 중인가 (현행 여부) | `search_law`의 [현행] 표시·시행일, 시행예정 개정(🔜) |
| 이 사안에 어느 시점 버전이 적용되는가 (적용 버전) | 적용 기준일을 정한 뒤 `legal_analysis`(mode=`applicable_law`, lawName·date·jo) 또는 `get_law_text`(`efYd=기준일`) |

적용 기준일은 사안의 성격과 근거를 밝혀 정한다. 과거 사안이라는 이유만으로 구법을 적용하지 않고, 최근 답변이라는 이유만으로 현행법을 적용하지도 않는다.

| 사안 성격 | 출발점 (법령에 특별한 규정이 있으면 그에 따름) |
|---|---|
| 신청에 따른 처분 | 처분 당시 법령 (「행정기본법」 제14조제2항, 처분 당시 법령을 적용하기 곤란한 특별한 사정은 예외) |
| 위반행위와 제재처분 | 위반행위 당시 법령. 이후 위반이 아니게 되거나 제재 기준이 가벼워졌으면 변경된 법령 (같은 조 제3항) |
| 효력 발생 전에 완성·종결된 사실관계 | 새 법령을 적용하지 않음 (같은 조 제1항) |
| 답변 발송 때 이행하는 절차 (처리결과 통지, 구제절차 안내 등) | 그 행위를 하는 시점의 현행 조문 (제14조에 직접 규정이 없는 일반 원칙) |

- 처리기한은 접수 때부터 진행하므로, 접수 뒤 발송 전에 관련 조문이 바뀌었으면 어느 버전을 적용할지 부칙으로 확인하고 불명확하면 `[확인 필요: 적용 기준일]`로 남긴다.
- 부칙(시행일·적용례·경과조치)이 위 출발점보다 우선한다. `applicable_law`가 "경과규정 신호 미발견"이라고 해도 발췌 결과일 뿐이므로 부칙 원문을 확인한다.
- 분리시행(조항별 시행일이 다른 개정)이면 인용하는 조항의 실제 시행일을 부칙에서 확인한다.
- 시행예정 개정이 있으면 인용 조항의 시행예정본 문언을 조회한다. 현행과 같으면 그 사실과 확인일을 기록하고 해소한다. 다르거나 확인하지 못했는데 민원인이 발송 후 이용할 기간·절차(예: 이의신청 기간)가 시행예정일에 걸치면 사안 적용 판단 칸에 `[확인 필요: 시행예정 개정 영향 — 담당자 확인]`을 남긴다(해소 전 발송 불가).
- 항·호 번호도 버전마다 다를 수 있다. 예: 「민원 처리에 관한 법률」 제27조의 "거부 시 거부 이유와 구제절차 통지"는 2022-03-15 기준 버전에서 제2항, 현행(2022-07-12 시행)에서 제3항이다. 「행정기본법」 제36조의 적용 제외 사항은 2025-06-01 기준 버전에서 제7항, 현행에서 제8항이다(2026-10-25 korean-law-mcp 조회).
- 적용 기준일이나 버전 선택이 불명확하면 단정하지 않는다. `[확인 필요: 적용 기준일 — 담당자·법무 검토]`로 남기고 해당 인용의 상태를 `재검증 필요`로 둔다.

## 절차 조문도 동일하게 검증

처리기한, 이송 의무, 보완요청 요건, 이의신청 기간 등 절차 근거(「민원 처리에 관한 법률」, 행정절차법, 행정심판법, 정보공개법 등)를 답변에 명시할 때도 실체 조문과 동일하게 검증한다. "처리기한 14일" 같은 일반 사다리를 기억으로 적지 않는다 — 기한과 의무는 민원 유형, 기관 규칙, 처분 여부에 따라 달라진다. `references/deadlines-and-followup.md`의 기준표와 `core/response-rules.md`의 구제절차 분기표는 출발점일 뿐이며, 답변에 인용하는 순간 검증 대상이 된다.

## 인용 상태와 확인 방법

상태는 발송 가능 여부를, 확인 방법은 어떻게 확인했는지를 나타낸다. 두 값을 따로 적는다.

| 상태 | 의미 | 발송 |
|---|---|---|
| ✅ 검증 | 공식 원문(도구 조회 또는 수기 확인)으로 조문 실존·문언·적용 버전의 시행일을 확인했고 불일치 의심이 없음 | 가능 |
| 재검증 필요 | 확인했으나 법령명·조번호·문언·시행일·적용 버전 중 불일치 의심이 남음 | 불가 — 의심을 해소해 ✅ 검증으로 바꾼다. 결론·근거·구제절차·처리기한에 영향이 없는 문장이면 빼고 발송할 수 있다 (`core/quality-checklist.md`) |
| ⚠️ 미검증 | 어떤 방법으로도 확인하지 못함 | 불가 — 확인 후 넣는다. 결론·근거·구제절차·처리기한에 영향이 없는 문장이면 빼고 발송할 수 있다 (`core/quality-checklist.md`) |

| 확인 방법 | 함께 기록할 내용 |
|---|---|
| 도구 | 사용한 도구명(예: `get_law_text`)과 법령 식별정보(MST 등) |
| 수기 | 확인한 공식 사이트(국가법령정보센터, 자치법규정보시스템 등)의 URL 또는 문서 식별정보와 확인자(담당자·작성자). 작성자가 원문을 직접 보지 못하고 담당자의 확인 결과를 전달받았으면 그 사실을 적는다 |

- 법률·시행령·행정규칙·조례·기관 내부 규정 모두 같은 상태 체계를 쓴다. 수기 확인도 공식 원문으로 의심 없이 확인했으면 ✅ 검증이다.
- 이전 버전 문서의 태그는 이렇게 읽는다: `행정규칙 수기` → 확인 방법 수기. 출처·적용 버전·확인일 기록이 있으면 ✅ 검증, 없으면 재검증 필요. 이전 `✅ 검증`(현행 조문만 확인) → 적용 버전·적용 기준일 기록이 있으면 ✅ 검증, 없으면 재검증 필요. `재검증 권장` → 재검증 필요(발송 불가).

검증에 실패한 인용이 침묵 인용이 되어서는 안 된다. 확인하지 못한 조문은 반드시 상태를 남기고, 발송본에서는 해당 문장을 빼거나 확인 후 넣는다.

## 인용 검증표 양식 (내부 검토표에 포함)

법령·규정을 인용한 답변은 내부 검토표에 다음 표를 포함한다. 조문 실존 확인(상태)과 이 사안에 대한 적용 판단을 다른 칸에 적는다. 조문이 실존해도 사안 적용 판단이 서지 않으면 발송하지 않는다.

| 법령·조문 | 출처(URL 또는 문서 식별정보) | 적용 버전(시행일) | 적용 기준일·선택 이유 | 확인 방법 | 확인일 | 상태 | 사안 적용 판단 |
|---|---|---|---|---|---|---|---|
| 민원 처리에 관한 법률 제16조제1항 | 국가법령정보센터, MST ○○○○○○ | 20XX-XX-XX | 이송일 — 발송 때 이행하는 절차 | 도구: `get_law_text` | 20XX-XX-XX | ✅ 검증 | 적용: ○○ 사무는 ○○기관 소관 |
| ○○교육청 ○○ 조례 제○조 | 자치법규정보시스템 URL | 20XX-XX-XX | 처분일 — 신청에 따른 처분 | 수기 | 20XX-XX-XX | ✅ 검증 | `[확인 필요: 요건 해당 여부]` |

위 행은 형식 예시다. 실제 답변에서는 매번 새로 조회해 채우고, 예시의 값을 옮겨 쓰지 않는다.

- 사안 적용 판단 칸에는 `적용` + 요건-사실 연결 요지, 또는 `[확인 필요: …]`를 적는다. `[확인 필요]`가 남으면 발송 불가.
- 법령 해석이 불확실하면 `[확인 필요: 유권해석 — 담당자·법무 검토]`로 남긴다.

## 실패 모드별 처리

| 상황 | 처리 |
|---|---|
| korean-law-mcp 부재·오류 | 공식 사이트(law.go.kr 등)에서 조문과 적용 버전을 수기 확인하고 출처 URL·적용 버전·확인일·확인자를 검증표에 기록. 조문 제목 대조와 시행예정 개정 여부도 함께 본다 → 의심이 없으면 ✅ 검증(확인 방법: 수기), 남으면 재검증 필요. 그것도 불가하면 ⚠️ 미검증 후 내부 확인 요청 |
| 조문 미발견 | 법령명·조번호를 재확인(`search_law` 재시도, 약칭·구법명·개정 전 조번호 의심) → 수기 확인 → 그래도 불확실하면 재검증 필요 |
| 행정규칙·조례 미조회 | law.go.kr 행정규칙·자치법규 검색에서 수기 확인 → ✅ 검증(확인 방법: 수기) 또는 재검증 필요 |
| 적용 버전 불명확 | `applicable_law`·부칙 원문 확인 → 그래도 불명확하면 재검증 필요 + `[확인 필요: 적용 기준일]` |
| 도구 결과끼리 시행일이 어긋남 (예: `search_law`와 `get_law_text` 머리글) | 분리시행 여부를 `applicable_law`와 부칙 시행일 조문으로 확인해 인용 조항의 실제 시행일을 정한다. 해소 전에는 재검증 필요 |

## 용어 자기점검

- 소관부처는 조직 개편으로 바뀐다. `search_law`가 돌려주는 현재 소관부처를 기억보다 우선한다.
- 위임과 위탁은 법적으로 다르다(내부 위임 vs 외부 위탁, 결정 주체가 달라짐). 바꿔 쓰지 않는다.
- 유사 용어(허가·인가·승인·신고 등)는 조문이 실제 쓰는 용어를 그대로 쓴다.
